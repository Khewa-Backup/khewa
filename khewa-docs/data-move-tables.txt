# Which tables come from live on upload day (see data-move-plan.md)
#
# DATA    = replaced by the live table (after its structure is upgraded to 9.2)
# REBUILD = rebuilt after the move (amazzingfilter index: module settings > re-index)
# SETUP   = kept from this 9.2 shop (all our fixes live here)
# SKIP    = not moved, left empty or as it is (login sessions: everyone logs in again)
#
# ps_configuration is SETUP, but these live values are copied over it on the day
# (the practice run lists every key that changed on live since 16 Oct, then each is decided):
#   - invoice / delivery slip / order numbering: PS_INVOICE_START_NUMBER, PS_DELIVERY_NUMBER, PS_INVOICE_PREFIX, PS_DELIVERY_PREFIX (+ shop rows)
#   - gift card, loyalty and POS counters/settings changed by staff since 16 Oct
#   - PS_CURRENCY_DEFAULT rates if changed (ps_currency conversion_rate)
#
# Exceptions on the DATA list (handled in data-move/merge.sh): ps_feature_flag, ps_cart_rule_type, ps_cart_rule_type_lang
# are kept from here; ps_product_attribute_lang is rebuilt; ps_cart_rule_compatible_types is not on live (emptied).
#
